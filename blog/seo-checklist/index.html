2026.11.19 SEO 技術メモ

リニューアルで検索の評価を落とさない
— 制作時に必ず確認しているSEOの技術チェックリスト

サイトを作り直したら、検索からの流入が減った。よく聞く話ですが、原因の多くはデザインでも文章でもなく、技術的な引き継ぎ漏れです。古いURLが404のまま残っている。canonical が実際とは違うURLを指している。確認用環境の noindex を本番で外し忘れている。どれも公開時に一度確認すれば防げます。先に結論を書くと、SEOで効くのは「何本書いたか」ではなく「評価を落とさない作り」と「伸びる記事に手を入れること」です。LiberaSpace が制作のたびに確認している項目を、そのまま公開します。

01まず全体像：6分野のチェックリスト

確認する項目は、大きく6つの分野に分かれます。分野ごとに、確認するタイミングも違います。

02リニューアル時は、評価を引き継ぐことが最優先

長く運営してきたサイトには、URLごとに評価が積み上がっています。作り直しで一番避けたいのは、それをゼロに戻してしまうことです。

  • 既存ページのURLは、できるだけ変えない
  • URLを変える・ページを統合する場合は、旧URLから新URLへ301リダイレクトする
  • 今のサイトで評価されている部分（title／description、テキストで書かれた事業説明や実績）は削らない
  • http→https、wwwあり／なしを1つにそろえ、canonical が実際に表示されるURLを指すようにする
  • 公開後は Search Console で、旧URLの404とインデックス登録の状況を確認する

表記の統一は見落とされがちです。株式会社 半谷のリニューアルでも、サイトのアドレス表記を1つに統一しました。同じページでも表記が何通りもあると、検索エンジンからは別々のページに見え、評価が分散するためです。

03ページ設計：1ページ1テーマ

  • 1ページ1テーマ、1記事1テーマにする
  • トップページは全体の要約と入口にし、詳しい内容は下層ページに置く
  • 同じテーマのページを複数作らない（評価の取り合いになる）
  • 関連ページ同士を内部リンクでつなぐ（記事⇔サービス、校舎ページ⇔料金ページ、記事同士）
  • 各ページに十分な情報量を持たせる

半谷では、1ページに4職種がまとまっていた採用情報を、施工管理・鉄骨加工・現場多能工・製図の職種別ページに分けました。「施工管理 求人」と検索した人が、その職種のページへ直接たどり着けるようにするためです。まとめページは一覧と入口の役割に絞り、内容の重複をなくしています。

04技術設定：検索エンジンとAIに正しく読ませる

見た目には出ない部分ですが、検索結果での表示とAIからの引用に直接関わります。

  • 全ページに、そのページだけの title と meta description を付ける
  • OGP を設定する。og:image のURLが実在するか、タグが二重に出力されていないかを確認する
  • canonical を指定する
  • 構造化データ（JSON-LD）を内容に合わせて入れる。Organization、LocalBusiness、Person、Article、BreadcrumbList、FAQPage、WebSite など
  • 記事の author を空欄にしない。@type（Organization か Person か）も正しく書く
  • sitemap.xml を自動で生成・更新し、Search Console に送信する
  • 似たドメインがある場合は、サイトマップで各サイトの役割を示す
  • robots.txt で、必要なページのクロールを止めていないか確認する
  • 確認用環境は noindex にし、本番公開時に外し忘れない
  • 見出しは h1〜h3 を正しい順番で使う
  • 画像には alt と、内容が分かるファイル名を付ける
  • 多言語ページには hreflang を設定する

効果が分かりやすかったのが、ハングル語学堂です。旧サイトは全ページの title が同じで、教室の情報を伝える構造化データもありませんでした。リニューアルでは、9校それぞれの住所・電話番号・受付時間、コースと料金、よくある質問を構造化データで整理し、全ページの title と description を教室名と所在地が伝わる内容に改めました。キーワードを並べただけの記述は、Google のガイドラインでは逆効果になるため取り除いています。

リニューアル後、AI検索での引用率は5倍に、お問い合わせ数は約1.5倍に増えました。Google 検索での表示回数は約25％、1か月のクリック数は約20％向上しています。

05表示速度と使いやすさ

  • 画像は圧縮し、表示サイズに合った大きさで WebP／AVIF を配信する
  • 埋め込み動画は、クリックしてから読み込む形にする
  • スマートフォンでの見やすさを確認する
  • PageSpeed Insights で Core Web Vitals を確認する
  • どのページからでも、問い合わせへ迷わずたどれるようにする

速度は、一つの大きな施策より小さな改善の積み重ねで決まります。半谷では、写真をすべて軽い形式に変換し、外部から読み込んでいた部品を自社サイト側に移し、フォントの読み込み方も見直しました。

06記事は本数より中身、新規よりリライト

記事の作り方

  • 導入文のすぐ後に、見出しへのリンク付きの目次を置く
  • 冒頭で答えを書く。一覧は画像だけでなく、文字の表でも載せる
  • 「よくある質問」を入れ、FAQPage の構造化データも付ける
  • 画像は大きくしすぎない（中央寄せで幅400〜480px、縦長は360px）。上下に約2emの余白を入れる
  • 日程などの事実は公式情報で確認する。推測では書かない

更新とリライトの考え方

  • 更新の回数そのものは評価されない。効くのは中身
  • 中身の薄い記事を量産すると、評価が下がるおそれがある
  • すでに10〜30位にいる記事を書き足すほうが、新しい記事を増やすより効率がいい
  • 日付だけを書き換える「見せかけの更新」はしない
  • 運用の目安は、月2〜4本の新記事と、四半期ごとの既存記事の見直し
  • Search Console で「表示回数は多いのにクリックが少ない記事」をリライトの対象にする
  • 順位は高いのにクリックされない記事は、まず title と description を直す
  • リライトしたら、URL検査から再インデックスを依頼する

ポイント

新しい記事を書く前に、Search Console で10〜30位の記事を探してください。ゼロから1本書くより、すでに評価されている記事に足りない情報を足すほうが、少ない手間で順位が伸びます。

07誰が書いたかを明らかにする

検索エンジンもAIも、出どころがはっきりした情報を優先します。

  • 記事に執筆者・監修者と、公開日・更新日を表示する
  • 執筆者の資格や経歴が分かるページを作り、記事からリンクする
  • 会社概要、運営者の情報、問い合わせ先、プライバシーポリシーを載せる
  • 実績は具体的な数字で書く。数字はクライアントに確認してから載せる

08よくある質問

リニューアルすると、検索順位は必ず下がりますか？

必ずではありません。URLの維持、301リダイレクト、既存コンテンツの保持を押さえれば、大きな下落は防げます。公開後は Search Console で404とインデックス登録の状況を確認します。

記事は頻繁に更新したほうがいいですか？

更新の回数そのものは評価されません。目安は月2〜4本の新記事と、四半期ごとの既存記事の見直しです。日付だけを書き換える更新は逆効果になりえます。

新しい記事を書くのと、古い記事を直すのはどちらが先ですか？

すでに10〜30位にある記事があれば、そちらの書き足しが先です。新規記事より少ない手間で順位が伸びやすいためです。

AIに引用されるために、特別な対策は必要ですか？

土台は通常のSEOと同じです。会社情報やよくある質問を構造化データで整理し、誰が書いた情報かを明らかにすることが、検索とAIの両方に効きます。

SEOは公開してから頑張るものと思われがちですが、実際には作る段階で8割が決まります。評価を落とさない形で作っておけば、その後の運用はずっと楽になります。自社サイトの現状が気になる方は、SEO・AI引用対策の30分無料診断でご確認いただけます。

SEO・AI引用対策のご相談

リニューアル時の引き継ぎから、公開後の定点観測とリライトまで対応しています。まずは30分の無料診断で、検索やAIでの現在の紹介状況をご確認ください。
